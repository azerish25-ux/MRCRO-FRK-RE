# Admissions and exclusions

The XML API implements the original `722ab0` mode-0 parser body. It returns owning byte strings; native input-buffer mutation, pointer identity, allocator identity, exception object layout and unwind/diagnostic lifecycle are outside its contract. It does not impose namespace rules, duplicate-attribute rejection or closing-name validation from a host XML implementation. Numeric entities use the source digit table, uint32 accumulation/wrap and source UTF-8 byte emitter. It does not normalize attribute whitespace or validate UTF-8 byte sequences. Only the returned bytes and the tested parse-error messages are compared; no error-object/runtime-unwind parity claim is made.

Adapter bounds are input ≤2 MiB, element recursion depth ≤128, allocated output nodes ≤32,768 including the document, and attributes per element ≤8,192. Bounds fail explicitly. Measured exact native AST maxima over the 86 standalone installed documents are 1,053,406 input bytes, depth 16, 13,321 nodes/document, 33 attributes/node, 13,118 children/node and 712 bytes/field. Thus the current raw data admits the canonical documents without substituting their positions or shapes.

The direct parser body accepts empty, whitespace-only, NUL-only and BOM-only documents, proven by unchanged `722ab0` instructions on an initialized owned document pool. The separate `6f6a90` empty-string constructor control stopped at an unmodeled call; it is retained as blocked and is not used to infer file-loader acceptance. Actual caller missing-root checks and constructor/error lifecycle remain separate.

All 24 widget-editor files are comma-separated widget/style compounds. The original standalone reader rejects their comma with `expected <`; the isolated style fragment accepts its duplicate attributes. This packet preserves that standalone behavior. The editor consumer's framing protocol is not yet implemented, and the packet does not reject duplicates as an explanation for those files.

Styles are element-tree **data snapshots**. Input and the selected inherited base have depth ≤128, ≤32,768 nodes, ≤8,192 attributes/node, ≤2 MiB total string bytes, and no embedded NUL. The separately expanded title is ≤4,096 bytes with no NUL and corresponds to the first raw `title` attribute. New key must be unique and an inherited base must already exist; invalid-definition failure ordering is adapter behavior, not native exception/lifecycle parity. The adapter checks these conditions before entering the preserved source-derived operation.

The owning map does not reproduce native XML-node pointer aliases. A non-inherited native definition registers the original node; callers of the portable data operation must keep corresponding original input immutable after registration when comparing subsequent snapshots. External mutation of registered source nodes and component/property callbacks are not covered. Inheritance's observed input-attribute consumption and child preservation are covered. All 400 installed standalone predefined-style subtrees contain only elements (594 nodes total); their largest combined string payload is 3,520 bytes. This measures profile admission, not execution of the complete native style loader on every scene.

There is no registry-count cap in this style data operation. Actual scoped string registries, include/for expansion counts, expression expansion lengths and output command maxima still need the native lowering pipeline audit. This packet adds no fixed-position or CSS fallback. It does not execute declarations, resolve a title, load a file, dispatch an `if`, run a loop, install/erase `with` bindings, instantiate a template or create Components.

The existing geometry prefix's positive-size admission is not asserted as a full-scene rule. No literal zero/auto/deferred dimension attributes were found in the 86 native ASTs, but expression-derived, absent, hidden, intrinsic and deferred zero sizes are still open. A tagged bounds failure is producer data until the real builder caller's continuation/termination semantics are proved. RuntimeLayout external-child entry, observer multiplicity, factory ownership, font/raster/paint and input lifecycle remain separate work.
